These workspace-wide instructions enforce data engineering governance across all users. Genie Code applies these rules to every response.

---

## Table Documentation Policy

- Every table MUST have a `COMMENT` clause describing its purpose.
- Every table MUST have `TBLPROPERTIES` with at least `"quality"` and `"domain"`. Do not set `"owner"` (reserved table property).
- Every table containing personal data MUST include `"contains_pii" = "true"` and `"pii_columns" = "<column_list>"` in TBLPROPERTIES.
- PII columns MUST be annotated with inline comments indicating risk level (e.g., `-- [PII: EMAIL - HIGH]`).
- Primary keys, derived columns, and PII columns MUST have column descriptions via `ALTER TABLE ... ALTER COLUMN ... COMMENT`.
- Unity Catalog tags (`quality`, `domain`, `pii`, `data_classification`) MUST be applied to all tables.

## Naming Conventions

- All table names MUST use `lowercase_snake_case` with layer prefixes: `bronze_`, `silver_`, `gold_`.
- No PascalCase, UPPERCASE, kebab-case, or camelCase.

## Audit Columns

- Every table MUST include `audit_timestamp` and `source_system` as the LAST columns in the SELECT.

## Pipeline Language

- All SDP pipelines MUST be written in SQL, not Python.

---

### Approach A: Direct Skills Reference (no MCP)

> Use this if skills have been uploaded to the workspace. Each skill is its own
> folder with a `SKILL.md` file (plus optional template markdown) at
> `Workspace/.assistant/skills/<skill-name>/`. Genie Code auto-loads a skill
> when the request matches its description. In chat, `@table-governance` (and
> the other skill names) still force a skill -- `@` is skill invocation, not a
> separate instruction syntax.

All pipeline authors must use the following skills when creating or modifying tables:

1. **@table-governance** -- Table and column documentation, TBLPROPERTIES, UC tags, PII labeling (apply first)
2. **@sdp-basics** -- Naming, audit columns, data quality constraints, SQL formatting
3. **@pii-management** -- PII detection, labeling, masking, and GDPR patterns
4. **@sentiment-analysis** -- AI-function patterns (sentiment, topic, extraction) for tables built from free-form text

### Approach B: GitHub MCP Reference

> Use this if enterprise standards are served from GitHub via MCP.
> Genie Code fetches the skill files directly from your GitHub repo.

## Skill source (hard rule)

Before writing any pipeline SQL, fetch each required skill from GitHub with
the MCP connection named `genie-code-skills-mcp`. Use that connection's
`get_file_contents` tool.

- Owner: `<your-github-org-or-user>`
- Repository: `<your-repo>`
- Branch: `main`
- Connection: `genie-code-skills-mcp`
- Tool: `get_file_contents` (on that connection only)

MUST:

- Call `get_file_contents` on `genie-code-skills-mcp` for every file you apply
- Apply only the bytes that tool returns

MUST NOT:

- Use `readSkillFile` or any built-in skill loader
- Read `.assistant/skills/` (user or workspace)
- Use `@table-governance`, `@sdp-basics`, `@pii-management`, or
  `@sentiment-analysis` as a fetch -- `@` loads workspace skills, not GitHub
- Auto-load skills from `AGENTS.md` instead of fetching
- Treat "the content looked the same" as compliance
- Fall back to local, cached, or auto-loaded skills if MCP fails

If `get_file_contents` fails, stop and report the error. Do not substitute
another tool.
