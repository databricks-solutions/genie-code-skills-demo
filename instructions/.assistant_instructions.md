### Approach A: Direct Skills Reference (no MCP)

> Use this if you have uploaded skills directly to your Databricks workspace.
> Each skill is its own folder with a `SKILL.md` file (plus optional template
> markdown next to it), under `Workspace/.assistant/skills/<skill-name>/` or
> `/Users/{username}/.assistant/skills/<skill-name>/`. Genie Code auto-loads a
> skill when your request matches its description. In chat, `@table-governance`
> (and the other skill names) still force a skill -- `@` is skill invocation,
> not a separate instruction syntax.

When creating or modifying SDP pipeline tables, always use the following skills:

1. **@table-governance** -- Apply table and column documentation standards (COMMENT, TBLPROPERTIES, column descriptions, UC tags). Apply this first for every table.
2. **@sdp-basics** -- Apply SDP naming conventions, audit columns, data quality constraints, and SQL formatting
3. **@pii-management** -- Identify, label, and annotate PII columns in tables containing personal data
4. **@sentiment-analysis** -- Apply when building tables that use AI functions (`ai_analyze_sentiment`, `ai_classify`, `ai_extract`, `ai_summarize`) on free-form text such as customer reviews, support tickets, or transcripts

For every table you create:
- Always apply the table-governance and sdp-basics skills
- If the table contains customer or personal data, also apply the pii-management skill
- If the table derives sentiment, topics, or entities from text via AI functions, also apply the sentiment-analysis skill

### Approach B: GitHub MCP Reference

> Use this if you are serving skills via a GitHub MCP server connection.
> Genie Code fetches the skill files directly from your GitHub repo.

## Skill source (hard rule)

Before writing any pipeline SQL, fetch each required skill from GitHub with
the MCP connection named `genie-code-skills-mcp`. Use that connection's
`get_file_contents` tool.

- Owner: `<your-github-org-or-user>`
- Repository: `<your-repo>`
- Branch: `main`
- Connection: `genie-code-skills-mcp`
- Tool: `get_file_contents` (on that connection only)

MUST:

- Call `get_file_contents` on `genie-code-skills-mcp` for every file you apply
- Apply only the bytes that tool returns

MUST NOT:

- Use `readSkillFile` or any built-in skill loader
- Read `.assistant/skills/` (user or workspace)
- Use `@table-governance`, `@sdp-basics`, `@pii-management`, or
  `@sentiment-analysis` as a fetch -- `@` loads workspace skills, not GitHub
- Auto-load skills from `AGENTS.md` instead of fetching
- Treat "the content looked the same" as compliance
- Fall back to local, cached, or auto-loaded skills if MCP fails

If `get_file_contents` fails, stop and report the error. Do not substitute
another tool.

## Quick Reminder

- Audit columns: `audit_timestamp`, `source_system` (as LAST columns)
- All tables need: layer prefix, COMMENT, TBLPROPERTIES with `quality` (and `domain` where known). Do not set `owner`.
- Add column descriptions for PKs, derived columns, and PII columns
- Bronze: WHERE clause filtering, CLUSTER BY AUTO
- Silver: CONSTRAINT clauses, data_quality_flag
- Gold: ROUND() for money; join same-pipeline tables by name (no `LIVE.` prefix)
- PII: Use income_tier/credit_tier derivation, mask emails/phones
